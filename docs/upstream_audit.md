- Official base: `apple/FastVLM-0.5B`
- Hub revision: `16375720c2d673fa583e57e9876afde27549c7d0`
- Local Transformers-cache copy: `/Volumes/data/huggingface/transformers/models--apple--FastVLM-0.5B/snapshots/16375720c2d673fa583e57e9876afde27549c7d0`
- Source weight SHA-256: `4c70bf1ae23f362b9a623706bffbd0830999ea55c821c0b3545c49bd988095a7`
- MLX conversion: `/Volumes/data/checkpoints/fastvla/models/apple-fastvlm-0.5b-mlx`
- Conversion operation: isolated offline checkpoint-format compatibility task using
  `python -m mlx_vlm convert`; no PyTorch model execution is used in training or inference.

The Apple `FastVLM-0.5B-fp16` MLX repository revision
`d241b8ae8acc23e319d79b1022fcba6a967046a3` was also inspected. With the pinned
MLX-VLM 0.4.4 loader, its `multi_modal_projector.*` parameter names do not match the
loader's `mm_projector` module. The repository therefore pins the converted local
checkpoint instead of silently ignoring mismatched weights.

Observed on the M4 / 32 GB machine with the converted checkpoint:

- Model load: approximately 1.2–4.7 s depending on cache state.
- Peak process RSS during a warm forward check: approximately 2.55 GB.
- FastVLM 1024-pixel frame to final language hidden state: approximately 0.32–0.41 s.
- Visual representation: 256 projected FastViTHD tokens plus the language hidden state.

These are local measurements, not Apple's published VLM TTFT results. Final latency
figures are generated by the benchmark script from the actual VLA checkpoint.

## MLX-VLM findings

- MLX-VLM contains a native FastVLM model with FastViTHD, a 2-layer GELU multimodal
  projector, and a Qwen2 language model.
- Its FastVLM forward path exposes task-relevant projected visual tokens and can pass them
  through the language model. Our action policy preserves a 4 x 4 spatial summary in
  addition to the final hidden state.
- MLX-VLM 0.4.4's PEFT helper calls `.freeze()` on FastVLM's non-`nn.Module`
  `CallableModuleList`. The project freezes the upstream model first and attaches the
  upstream `LoRaLayer` explicitly. This is still real LoRA: gradients reach the adapter
  `A`/`B` matrices and optimizer updates change them.
- Training uses batch size one for the language path because the pinned Qwen2 call does not
  accept a padding mask. Action-head-only training uses batched cached features.

## Data and simulator mapping

Local dataset: `/Volumes/data/huggingface/lerobot/lerobot/metaworld_mt50`.
It contains 2,500 episodes, 204,806 frames, 49 task instructions, 80 Hz control, embedded
480 x 480 RGB images, 4-D state/action vectors, and benchmark success flags. It is
licensed Apache-2.0 by its Hub card.

The selected tasks are mapped by exact instruction text from LeRobot's Apache-2.0
`metaworld_config.json`:

| Dataset instruction | Meta-World v3 task |
| --- | --- |
| Press a button from the top | `button-press-topdown-v3` |
| Push the puck to a goal | `push-v3` |
| Reach a goal position | `reach-v3` |

Evaluation uses the same `corner2` camera, an inverted-axis correction, 480 x 480 render,
4-D actions, 80 Hz environment semantics, and the environment's native `success` flag.

## License decision for model publication

The checkpoint card and LICENSE file both identify `apple-amlr`. The agreement permits use,
modification, derivative creation, and distribution for non-commercial Research Purposes.
Redistribution must include the Agreement, the exact attribution sentence, identification
of the artifact as a derivative, disclosure of modifications, and must not imply Apple
endorsement. A trained action head and LoRA adapters attached to Apple weights are treated
as potential derivatives, conservatively.

Decision: a completed FastVLA checkpoint may be considered for a research-only Hugging Face
release only after restoration/inference validation. It must use `license: apple-amlr`, carry
the complete agreement and required attribution, identify itself as an unofficial derivative,
disclose FastVLM LoRA training and the action head, and state that only non-commercial
research use is intended. If any unresolved licensing conflict remains, weights/adapters stay
private or local and only MIT-licensed code, Apache-2.0 source-referenced protocols, and
measured results are published.
